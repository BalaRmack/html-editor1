# SmartScreen: почему появляется окно и как его убрать

Короткий ответ: **полностью и навсегда — только подписью Authenticode сертификатом,
которому доверяет Microsoft.** Всё остальное — либо временные обходы для пользователя,
либо сбор репутации. Ниже — что именно происходит, какие варианты реально работают,
сколько стоят и что уже сделано в этом репозитории.

---

## 1. Что именно показывает Windows

Два разных окна, их постоянно путают:

| Окно | Когда | Причина | Что убирает |
|---|---|---|---|
| **«Windows защитила ваш компьютер»** (синее, SmartScreen) | при запуске скачанного из браузера `.exe` | у файла есть метка «из интернета» (Mark-of-the-Web, MotW) и **нет репутации** у этого хеша/издателя | репутация; подпись ускоряет её накопление |
| **«Неизвестный издатель»** (жёлтое, UAC) | при запросе прав администратора | в файле нет подписи | **только подпись** |

Verdant Launcher ставится без прав администратора, поэтому второе окно у нас не
появляется. Первое — появляется, и подпись его **не отменяет мгновенно**: с 2024 года
Microsoft убрал «мгновенный обход» даже для EV-сертификатов. Подпись даёт другое:
издателя с именем, накопление репутации **издателя** (а не только конкретного файла),
и отсутствие «Unknown publisher» в системных диалогах.

Метку MotW ставит не Windows, а программа, которая скачала файл: браузер, почта,
мессенджер. Файл, скачанный самим лаунчером (наш апдейтер качает `.exe` по HTTPS и
запускает его), метку обычно **не получает** — поэтому обновления внутри лаунчера идут
без синего окна, а первая установка из браузера — с ним.

## 2. Что не работает (проверено, не тратьте время)

| Идея | Почему не работает |
|---|---|
| Пересобрать exe «по-другому» | хеш меняется → репутация обнуляется, окно возвращается |
| Самоподписанный сертификат (`New-SelfSignedCertificate`) | пользователь не в вашем Trusted Root → подпись недействительна, SmartScreen не доверяет |
| Отдать файл в zip / 7z | Explorer переносит MotW на распакованные файлы |
| Другой хостинг / свой домен | репутация привязана к файлу и издателю, не к URL |
| «Подписать» позже, поверх | подпись ломается при любой модификации exe; подписывать надо то, что отдаёте |
| Попросить Microsoft «разрешить» файл через форму | форма WDSI лечит **ложные срабатывания антивируса**, а не отсутствие репутации в SmartScreen |

## 3. Что работает

### 3.1. Сертификат code signing (единственный настоящий способ)

С июня 2023 года правила CA/Browser Forum требуют, чтобы закрытый ключ жил на
сертифицированном носителе (USB-токен или HSM) и **не экспортировался**. Это значит:
«положить `.pfx` в GitHub Secrets» больше нельзя — так работают только устаревшие и
самоподписанные сертификаты. Живые варианты:

| Вариант | Цена (ориентир, 2026) | Кому доступно | CI |
|---|---|---|---|
| **Azure Artifact Signing** (бывш. Trusted Signing) | ~$9.99/мес | организации US/CA/EU/UK; физлица только US/CA | идеально: OIDC + `Invoke-TrustedSigning` |
| **OV-сертификат + cloud HSM** (DigiCert KeyLocker, SSL.com eSigner, Sectigo) | $130–690/год | по проверке личности/юрлица; доступность зависит от страны | хорошо: vendored CLI |
| **OV/EV + USB-токен** | $130–790/год | там же | только self-hosted runner с воткнутым токеном |
| **EV-сертификат** | дороже OV | для драйверов и требований закупок | как выше |

Два важных факта, которые продавцы сертификатов до сих пор пишут иначе:

1. **EV больше не даёт мгновенного прохождения SmartScreen.** Microsoft изменил это
   поведение в 2024 году; и OV, и EV набирают репутацию одинаково. Платить за EV
   «ради SmartScreen» смысла нет.
2. **Подпись ≠ отсутствие окна в первый день.** Новый издатель начинает с нуля:
   синее окно может появляться, пока не накопится история загрузок. Чем дольше вы
   подписываете **одним и тем же** издателем, тем быстрее репутация переносится на
   новые версии.

Для разработчика в РФ практическая картина такая: Azure Artifact Signing недоступен
по географии, международные CA с 2022–2023 почти не выдают сертификаты резидентам РФ.
Реалистичный порядок действий: (1) жить с окном и честной инструкцией, (2) при
появлении юридического лица/резидентства вне РФ — сразу подпись, (3) российские УЦ
для SmartScreen бесполезны: их корни не входят в доверенные Microsoft.

### 3.2. Репутация (медленно, но бесплатно)

* стабильный издатель: не менять `productName`/`publisherName`, подписывать все релизы
  подряд;
* объём загрузок с GitHub Releases — SmartScreen считает и его;
* каждая новая версия — новый хеш: репутация **файла** сбрасывается, репутация
  **издателя** (после подписи) — нет.

### 3.3. Обходы для пользователя (то, что можно дать прямо сейчас)

```powershell
# Снять метку «из интернета» до запуска
Unblock-File .\Verdant-Launcher-1.2.0-Setup.exe
```

или: правый клик по файлу → «Свойства» → внизу «Разблокировать» → «ОК».
Либо в самом окне SmartScreen: «Подробнее» → «Выполнить в любом случае».

Это ровно то, что написано в релизных заметках. Так делает большинство небольших
лаунчеров, и это честнее, чем самоподписанный сертификат с инструкцией «установите
наш корень в доверенные».

### 3.4. Каналы доставки без MotW

* **обновления внутри лаунчера** — уже так: файл качает наш код, метки нет, окна нет;
* **winget** (`winget install VerdantLauncher`) — установщик скачивает сам winget,
  метка обычно не ставится; требует манифеста в репозитории winget-pkgs.

## 4. Что уже сделано в репозитории

Подпись подключена так, что включается **одним секретом** и не мешает обычным сборкам.

```
GitHub → Settings → Secrets and variables → Actions → New secret
   VERDANT_SIGN_CMD = <команда вашего подписывающего CLI с {file}>
```

Примеры значения:

```text
# DigiCert KeyLocker
smctl sign --keypair-alias verdant --input {file}

# SSL.com eSigner
java -jar CodeSignTool.jar sign -username <user> -password <pass> -credential_id <id> -input_file_path {file} -override

# USB-токен на self-hosted runner
signtool sign /sha1 <THUMBPRINT> /tr http://timestamp.digicert.com /td sha256 /fd sha256 {file}

# Azure Artifact Signing (когда появится доступ)
powershell -NoProfile -File scripts/azure-sign.ps1 -File {file}
```

Порядок в пайплайне (`release.yml`, `ci.yml`):

1. `electron-builder --dir` → `release/win-unpacked/`;
2. **подпись `VerdantLauncher.exe`** — до упаковки в zip, иначе внутри payload останется
   неподписанный файл (он же копируется в `%LOCALAPPDATA%` и работает как деинсталлятор);
3. `make-payload` → `app.zip`;
4. сборка bootstrapper → `Verdant-Launcher-<version>-Setup.exe`;
5. **подпись setup.exe**;
6. `Verify Authenticode signatures`: `Get-AuthenticodeSignature` по обоим файлам.

Правила шага проверки:

* секрет не задан → job зелёный, но появляется предупреждение `Сборка без подписи`;
* секрет задан → `Status` должен быть `Valid`, **и** должна быть метка времени
  (`TimeStamperCertificate`), иначе job падает. Без таймстампа подпись умирает вместе
  с сертификатом, и старые версии начинают ругаться «срок действия истёк».

Скрипт подписи — `scripts/sign-artifact.mjs`, покрыт `tests/signing.test.ts`
(подстановка `{file}`, кавычки в путях с пробелами, падение при ошибке CLI, no-op без
секрета).

## 5. Чек-лист, если решили покупать сертификат

- [ ] Тип: **Code Signing** (Authenticode), не S/MIME и не TLS.
- [ ] Есть ли **cloud HSM / CI-интеграция** у CA (KeyLocker, eSigner, Trusted Signing) —
      без этого подпись в GitHub Actions невозможна.
- [ ] Проверят ли вашу юрисдикцию (для РФ чаще всего ответ «нет»).
- [ ] Срок и цена продления; сколько издателей/ключей входит.
- [ ] Тарифицируется ли таймстамп.
- [ ] После выпуска: `signtool sign /tr ... /td sha256` → `Get-AuthenticodeSignature`
      должен показать `Valid` и `CN=...` вашей компании.
- [ ] Первые релизы после покупки: предупредить пользователей, что окно может
      оставаться, пока репутация не наберётся (это нормально и ожидаемо).
